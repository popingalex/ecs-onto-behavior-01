# 布局、操作与视觉规范

## 产品界面骨架

编辑与演练共用一个工作台。全局功能栏只保留项目、建模、场景、逻辑、运行、复盘六个入口；二级对象在左侧资源树内出现。模型/场景/程序是资产，运行/分支/提交是执行对象，两组导航不混排。面包屑展示“项目 / 资产或运行 / 当前对象”；上下文栏常驻模式和版本。

| 区域 | 1920×1200坐标 | 内容 | 行为 |
|---|---|---|---|
| 顶栏 | x0 y0 w1920 h56 | 品牌、项目切换、保存状态、用户角色 | 固定，不放密集字段 |
| 功能栏 | x0 y56 w72 h1116 | 六主入口、快捷键提示 | 选中项以背景和文字描述区别 |
| 上下文栏 | x72 y56 w1848 h48 | 页面名、版本/分支/commit、主操作 | 编辑显示draft/revision，运行显示commit |
| 资源树 | x72 y104 w256 h1068 | 资产或实体/批次树 | 独立滚动与搜索 |
| 主工作区 | x328 y104 w1248 h1068 | 表格/图/视口；下部可停靠面板 | 主内容水平空间优先 |
| 检查器 | x1576 y104 w344 h1068 | 选中对象配置、输入输出、关联 | 不随主表滚动 |
| 状态栏 | x0 y1172 w1920 h28 | 数据状态、资源就绪、当前时间 | 错误不只藏在此处 |

图编辑和调试页在主工作区下方划264高面板。普通表单页无需占位调试面板。区域之间6px拖动柄，在实际组件布局中扣除；原型图以边界线展示。宽度1440时左树220、检查器320、主区余量；低于1280先收起资源树与检查器，禁止将14px正文缩成10px。全屏画布临时隐藏面板，Escape恢复。

## 视觉与信息密度

采用浅灰工作区、白面板、深蓝文字、青绿色主色。设计变量：bg=#F3F6FA、surface=#FFFFFF、ink=#162A40、muted=#64778B、border=#DCE4EC、primary=#087F8C、success=#17856B、warning=#B67714、danger=#C14555、purple=#7565AF。警告与错误有文字和图标，不能只用颜色。

正文14–16，辅助说明12–13，表头13，页面标题20–24。表格行40，表头40，输入36，按钮36，面板标题48，标签28，圆角6；图节点宽220–260、标题40、端口行28；图内可读字号14。间距4/8/12/16/24。数值右对齐、等宽数字；单位与数值间留空格。较长稳定ID在辅助行或tooltip完整可见，核心业务名不得全部截成省略号。

所有画布节点至少有标题、类型、输入/输出端口和一条语义摘要。不能用只有标题的方框代表复杂system。图例常驻：数据边青色实线、执行边灰色实线、显式产物紫色虚线；是否为控制/数据取决于业务定义，外观不能决定执行。

## 值与状态表达

| 数据状态 | 显示 | 可操作性 |
|---|---|---|
| 0 / false / [0,0,0] | 原值 | 正常合法值 |
| null | 未设置 | 仅nullable允许 |
| 属性不适用 | — | 不生成编辑值 |
| 未获准贡献 | 请求 / 自身暂存预览 | 不得标为已生效 |
| 裁决尚未运行 | 待裁决 | 禁止用0占位 |
| 来源未知 | 未记录来源 | 不从当前状态补造历史 |
| 已提交值 | 值+commit | 可追溯；历史只读 |

状态标签最少区分：草稿、已保存、校验过期、校验失败、已发布、排队、计算中、已提交、播放中、历史查看、离线。保存状态和发布状态分别显示。历史查看常驻黄色条“正在查看c042，主分支头c043”；回到最新是显式动作。

## 命令、撤销与错误反馈

编辑操作写入工作区command stack。输入焦点离开时做字段校验，保存时做对象校验，发布时做跨对象语义校验。撤销/重做作用当前草稿，运行命令撤销只能按命令生命周期执行；已提交业务不靠Ctrl+Z回滚，应建立分支或发补偿操作。

发布和结算是异步动作，有pending状态和幂等键。成功提示必须显示新version/commit；失败保留原状态和可修正输入。字段错误在字段旁、图错误在端口旁、跨对象错误在可跳转诊断列表出现。全局toast只做确认，不承担唯一错误解释。

## 焦点与辅助使用

Tab顺序按左到右、上到下；弹层锁定焦点，关闭返回触发控件；图节点能从列表选择并打开检查器。中文IME组合期间不触发快捷键。高对比文字、状态图标与文字并存。降低动画设置只停装饰动效与过渡，不改模拟步长、事件顺序和结果。

## UI与core责任

UI负责编辑草稿、展示诊断、格式化与导航；core负责类型/单位/作用域检查、执行计划、贡献分配、确定性与历史。UI不得根据连线形状、线程完成顺序或动画位置自行裁决业务。组件库提供表格/节点画布不等于提供这些语义。
