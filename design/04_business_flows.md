# 页面中的业务流转

## 一、从空白模型到首次演练

```mermaid
flowchart TD
 A["P02 定义类型与关系"] --> B["P03/P04 属性、单位、约束"]
 B --> C["P05/P06 实体与场景模板"]
 C --> D["P07 场景装配，P08 检查实体"]
 D --> E["P10 查询，P14 内部程序"]
 E --> F["P11 绑定system，P12 外层调度"]
 F --> G["P13 并发诊断，P16 联合约束"]
 G --> H["P18 校验与发布"]
 H --> I["P19 新建运行，P20 首回合"]
 H -->|"错误定位"| E
```

页面呈现：对象创建后进入草稿；每步的引用选择器只选已存在且兼容的对象。发布页面统一固定版本。首次进入运行不自动结算。场景初值与模板默认值可能不同，P05显示默认、P07显示实例覆盖，P20显示运行值。

## 二、双路冷却与裁决

```mermaid
flowchart TD
 S["旧状态c042：F01 100°C"] --> A["cool-A 请求−50 K；暂存50°C"]
 S --> B["cool-B 请求−50 K；暂存50°C"]
 A --> R["P23 额度80 K，比例0.8"]
 B --> R
 R --> V["获准−40/−40 K；最终20°C"]
 V --> C["原子提交c043"]
 C --> T["P24 属性版本与执行输入"]
```

P12显示并行组，P14显示产生请求的节点，P22按实体展示旧值/暂存/请求/获准/最终，P23解释分配，P24追踪输入版本。不是把最终温度20°C直接写进五个页面的静态文本。

|火源|旧温度°C|A/B请求K|A自身预览°C|获准A/B K|最终°C|
|---|---:|---|---:|---|---:|
|F01|100|−50 / −50|50|−40 / −40|20|
|F02|80|−50 / −50|30|−30 / −30|20|
|F03|60|−40 / −40|20|−20 / −20|20|

本例明确采用同温恒温冷源的冷却额度模型。不扩展为不同冷源、同时加热、有限热容量下的通用物理定律。若接入真实热量守恒，应替换领域求解器与关联效果契约。

## 三、提前接替与不满足分支

```mermaid
flowchart TD
 A["P17 策略：至少1车且水量≥50%"] --> B["420s：V01=5500 L，100 L/s"]
 B --> C["预测425s触及5000 L"]
 C --> D{"合格接替车存在？"}
 D -->|"V02=9000 L，4s到场"| E["P21 派遣获准"]
 E --> F["424s交接；V01停止耗水"]
 F --> G["430s：V01=5100，V02=8400 L"]
 D -->|"V02故障或无位置"| H["V03仅40%，不可接替"]
 H --> I["425s之后未满足；末水4500 L"]
```

P28展示时间区间与候选排除原因；P25区分预测、派遣、到达、交接事件。V02到达前在前往状态满足策略“前往或处置”资格，但V01按更严格的到场交接规则保持处置，避免物理服务中断。两车短暂重叠符合“至少1辆”，不得误用“恰好1辆”。

## 四、来源分析与反事实

```mermaid
flowchart TD
 A["P20 选F01最终温度"] --> B["P24 展开属性来源"]
 B --> C["P22 检查A/B实际输入"]
 B --> D["P23 检查获准贡献"]
 D --> E["P26 从c042建个人分支"]
 E --> F["停用cool-B后重新计算"]
 F --> G["P27 同430s对比：20/50°C"]
```

来源图解释程序如何得到结果；事件链解释已记录的业务关系；分支比较对同一基准和时间的结果做反事实检查。三者跳转互通，不能把单条时间顺序当因果证据。
